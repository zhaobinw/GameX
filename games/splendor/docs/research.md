# 璀璨宝石经典基础版：复刻调研

调研日期：2026-09-12。用户已选择经典版基础游戏，采用 Pascal Quidault 插画。目标是忠实复现官方玩法与组件，不创作变体。

## 结论

可以复用开源项目的数据与已有卡面来搭建本地环境；**不能不经审核直接复用整套规则实现**。此次源码审计发现了贵族数量错误、筹码上限处理错误、漏掉暗抽以及强制支付策略等问题。

当前选择：复用 MIT 项目 `roeey777/Splendor-AI` 的基础数据，独立实现按官方规则运作的引擎。已搭出中文同机牌桌，并保留完整行动空间供后续 AI 使用。没有新增规则、卡牌或自制替代插画。原画授权出处与完整视觉签核仍未完成，因此不把当前版本称为“完全 1:1 成品”。

## 核心玩法与实现约束

游戏的策略来自公开市场的争夺、永久折扣积累、有限筹码的周转以及贵族门槛。发展卡购买后提供永久颜色折扣，有些同时增加声望；贵族按已购卡的颜色数量到访。筹码本身不计入贵族条件。

下列约束提炼自经典规则第 2–4 页；边缘措辞另与新版规则第 2 页交叉核对，不以网络玩家变体为依据。

| 环节 | 必须保留的行为 |
| --- | --- |
| 组件 | 90 张发展卡，分为 40 / 30 / 20；10 位贵族；5 色各 7 枚宝石及 5 枚黄金 |
| 开局 | 三层独立洗牌，各亮 4 张；2 / 3 / 4 人使用每色 4 / 5 / 7 枚、贵族 3 / 4 / 5 位；黄金始终 5 枚 |
| 轮序 | 最年轻玩家先手，顺时针，每次一个主行动 |
| 取不同色 | 通常取 3 色各 1；不足 3 个可用颜色时取剩余颜色各 1，不拿黄金 |
| 取同色 | 取前该色池中至少 4 枚，才能取 2 枚 |
| 预留 | 公开市场或任一非空牌堆顶；手牌上限 3；有黄金则取 1，无黄金也可预留；不能弃预留牌 |
| 购买 | 公开牌或自己的预留牌；先扣永久折扣，再付筹码；黄金可替任意色；付款回池；可零筹码购买 |
| 补牌 | 公开卡离开原位后立刻补同层顶牌；对应牌堆空则留空 |
| 筹码上限 | 回合中可以超过 10；结束前归还到 10，可归还旧筹码、新筹码或黄金 |
| 贵族 | 回合末必须检查；满足一位自动来访，满足多位自选一位；不花额外行动，不消耗折扣；每位 3 分 |
| 终局 | 达到至少 15 分触发当前轮的最后阶段；所有人行动次数相同后比较声望，再比已购卡数较少者；仍平则共胜 |

数字化时的关键区别：`return` 与 `noble` 是主行动后的选择阶段，并非下一回合。达到 15 分不是立刻胜利。只自动选择“最省黄金”的付款会删掉合法策略，因此保留所有精确支付组合。手牌公开历史可以被记住，盲抽的身份不得通过日志、观察或动作列表泄漏。

## 数据核对结果

`scripts/audit-data.py` 将卡牌标准化为 `(层级, 折扣颜色, 分数, 白蓝绿红黑费用)` 后进行多重集合比较，保留重复记录计数，避免只数条目而漏查替换卡。

- 本地 90 卡 = MIT 原表 = splendimax CSV = 实体照片项目核对表：零差异。
- 本地 10 贵族 = MIT 原表 = seal256 常量：零差异。
- 费用没有靠颜色循环猜测生成；部分卡费用不具备简单循环对称性。
- 固定提交、来源 URL、SHA-256 和执行结果见 [data-audit.json](data-audit.json)。

这些项目可能共享数据来源，**多表一致不等于出版商认证，也不等于已经人工逐张核验全部实体牌**。目前保留这个验证边界，不把社区 README 中的“完整复刻”直接升级为事实。

由于目标是不创造新版本，“素材创意”在此转化为**官方组件的来源、映射与数字化摆放**：

| 元素 | 当前来源与处理 | 仍需完成 |

| 三层牌背 | 当前只提供层级、余量及暗抽操作按钮，不假装它是官方牌背 | 找到并验证经典版三种原背面 |

没有使用周年新版插画、AI 生成场景、替代主题、虚构贵族名称或原创音效。原图缓存与来源清单分离：Git 保存脚本、映射、哈希和第三方说明，原图保留于本地忽略目录。来源许可情况见 [NOTICE](../third_party/NOTICE.md)。

## 验收与尚未消除的差距

已落地的可运行层：官方基础规则、完整基础数据、2–4 人配置、经典卡面界面、观察隔离、确定性回放。规则场景与自动对局结果单独记录于 [validation.md](validation.md)。

“完全复刻”的验收尚须包括：

1. 与指定实体经典版本的全部卡面、贵族、牌背、筹码逐项签核；确认地区/印次是否存在外观差异。
2. 补齐高质量原版牌背与干净筹码原图，记录对应来源及授权出处。
3. 使用实体对局或另一套经人工验证的规则裁判，逐行动对比完整状态。现有复盘测试属于同一引擎自洽检查，不能替代独立裁判。
4. 官方基础规则没有给出“无任何合法行动”的完整处置条文。引擎此时不自创跳过或判平；如遇到可达实例，须按官方澄清处理。当前 30 局验证未遇到此情形。

在线多设备身份隔离、强 AI、训练、排位和扩展均不属于当前基础环境的完成声明。
