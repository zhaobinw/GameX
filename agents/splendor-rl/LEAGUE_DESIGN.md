# V3：从单一攻略到多对手对抗学习

## 复盘与研究

2026-09-12，本机已完成的人机对局：人类先手，26 回合，18:13。旧模型前 3 回合连续预留，开局两张预留卡直到结束也未买下，第 6 回合支付全部 3 枚黄金买一张 2 分卡。这是目标占位和资源分配可能失衡的案例，不是单凭一局就能证明的普遍缺陷。完整复盘与 26 条人类决策保存在忽略目录 `runs/human-feedback/`，不提交到公共仓库。

参考来源（查阅日期 2026-09-12）：

- [Brandon Stoker 的玩家攻略](https://boardgamestrategy.blog/2017/02/06/splendor-strategy/)：按场上牌规划目标、重叠贵族、预留阻断、灵活改变路线。属于玩家经验，不是普适最优规则。
- [玩家对冲分、黄金与阻断的讨论](https://www.reddit.com/r/boardgames/comments/knmx3f/splendor_whats_your_strategy/)：重点关注行动效率，而非只看宝石总成本。我们将它视为可检验的策略假设。
- [AlphaStar 原论文](https://storage.googleapis.com/deepmind-media/research/alphastar/AlphaStar_unformatted.pdf)：多样化联赛与 PFSP 优先安排难以战胜的对手，降低只适应当前自我对手的风险。本项目只实现小规模冻结对手联赛，不声称复现完整 AlphaStar。
- [cestpasphoto 派生实现](https://github.com/lyquentxy/splendor)：提供 MCTS 与预训练权重，但 README 明确说明拿取/归还行为存在规则限制，不能直接替换本项目官方基础版引擎。
- [BreckEmert/Splendor-AI](https://github.com/BreckEmert/Splendor-AI)：作者强调长周期资源承诺、DDQN、经验重放。其“超人类”描述是作者自述，平均回合数不足以证明人类胜率；动作空间经过启发式处理，不能直接作为本项目完整规则基准。

未发现并核验可直接使用、许可证清晰的大规模高手完整轨迹数据集。攻略文本不能伪装成真实玩家对局。没有下载或执行上述开源模型；本次实现独立编写，使用已有完整引擎。

## 本轮落地

保留 433 维观察、73 维候选动作特征的策略/价值网络及全部合法动作，兼容旧权重。模型运行时仍只输出网络评分最高的合法动作，不混入教师分数。

训练对手包括旧版确定性策略、固定攻略教师、冲分型、发展/贵族型、拦截型、贪心基线，以及每 4 代加入的冻结新模型。风格教师来自已有公开特征的不同权重，是对手多样性假设，不是新增规则。训练时只更新学习者轨迹，对手采用固定决策，避免旧实现以随机采样弱化对手的问题。

PFSP 权重为 `0.08 + (1 - (wins + 2)/(games + 4))²`，再归一化；胜负统计指数衰减，真实共享胜利按胜局份额计算，截断不算平局也不更新对手统计。均匀下限使容易的对手仍有机会出现。

PPO 使用每座位 GAE(λ=0.95)、终局胜负、学习率 1e-4、每批 3 epochs、KL 早停和梯度裁剪。本轮撤除教师模仿损失，允许超越攻略评分；不添加“多拿牌就加分”之类会偏离真实胜利目标的奖励。

训练、选模、最终检验使用三个分离的种子域；每个评估牌局成对交换双方座位。选模取六种对手的平均胜局份额，未完成局按零计入选模，不借删掉截断抬高分数。最终只检验选中的一个候选，保存逐局结果，可按配对牌局计算区间。不能依据训练胜率、模型代数或一局赢人宣称“最强”。

## V4 稳定化变体

V3 的独立检验未证明改进，因此没有部署。V4 从同一旧模型重新开始，换用新的训练、验证、留出种子；每 8 次更新用每对手 120 局验证，训练 64×128 局。PPO 增加 0.03 教师软标签损失、0.08 对旧策略的 KL 约束，熵系数降为 0.003，防止稀疏胜负学习过快破坏已有策略。V3 和 V4 均完整保留失败或退步结果。

最终报告按同一牌局的两个换座位结果组成一组，再对整组 bootstrap 10,000 次。平均提升的区间以同一牌局在所有对手下的平均差计算，保留跨对手相关性。自动发布门槛：对旧模型的胜局份额 95% 区间下界超过 50%，且多对手平均提升区间下界超过零。截断按零计入此门槛，并单独披露数量。

V4 额外在查看最终留出结果之前固定增加另一种子域的 600 局旧版正面对照；与原有 200 局合计 800 局，报告合并胜局份额和按牌局配对的区间。候选不在复验过程中调整，发布门槛使用这固定 800 局的正面对照与原六对手平均提升区间。

## 真人经验路径

`replay_examples.mjs` 接受完整合法的终局复盘，逐步从当时该座位的 `observe` 生成训练输入并标注真实动作索引；不把复盘里的牌堆、种子或对手暗牌当输入。未结束、动作非法的轨迹直接拒绝。

积累更多真人对局后，可按玩家/整场切分训练与留出数据，进行小权重行为克隆或胜局自模仿，再与联赛 PPO 混合。应保留失败局用于价值估计和薄弱局面分析；不能把失败局所有动作都标错，也不能把赢家每步都当最优。本轮仅转换用户已完成的一局作诊断，没有把 26 步当作大规模高手数据训练。

## 下一阶段

优先验证信息集搜索：只从公开信息采样未知牌，模拟对手回应；终局使用精确得分及同分卡数规则，未终局使用价值网络。需要处理暗抽层级记忆、随机补牌和策略融合，不能把真实隐藏状态直接交给 MCTS。通过相同时间预算的独立评估后，再将搜索访问分布蒸馏回网络。

更大的注意力网络、专门学习克制冠军的 exploiter、跨联赛经验重放均属后续实验；本轮没有把未实现的模块列为已完成成果。

## 运行

```bash
.venv/bin/python league_train.py --source runs/knowledge-v2-dev/latest.pt --run runs/league-v3 --updates 24 --episodes 128 --workers 8 --validation-games 40 --holdout-games 200
node replay_examples.mjs runs/human-feedback/human-game.json runs/human-feedback/examples.json 0
```

输出包括配置和源码哈希、对手胜负统计、逐代参数、选模明细、独立留出逐局结果及 `best.pt`。`latest.pt` 用于保留最新进度，不能默认当成最佳模型。当前联赛命令是单次实验；可从 `--source` 开启新实验，但不是精确恢复整个联赛状态。
