# Splendor 自我对弈强化学习设计（V1 基线）

当前默认推荐方案与强人类路线见 [V2 设计](STRONG_PLAY_DESIGN.md)。下文保留为首轮实验的算法定义，不能当作 V2 的参数说明。

## 目标与选择

第一阶段建立可重复的“采样 → 策略更新 → 历史对手 → 独立评估 → 保存 → 观战”循环。Splendor 的牌堆与预留牌含隐藏信息，不能将完整状态输入网络，也不把确定性完全信息搜索直接称为正确的 AlphaZero。

选用 PPO clipping 目标，采用完整对局的按座位 Monte Carlo advantage。算法依据 [Schulman 等，Proximal Policy Optimization Algorithms](https://arxiv.org/abs/1707.06347)。不实现 GAE：轮流行动的不同玩家不能直接串成同一条时序计算优势，第一版保留每个模型座位的独立轨迹，用实际终局效用减去当时价值预测，减少实现歧义。

历史对手池用于缓解当前策略对自身过拟合，不宣称收敛到 Nash 均衡。[Heinrich 与 Silver 的 NFSP 研究](https://arxiv.org/abs/1603.01121)说明了不完全信息游戏中自我对弈的难点；本项目没有实现 NFSP 的平均策略网络或其理论性质。

## 观察与动作

唯一入口为原引擎 `observe(state, currentPlayer)` 与 `legalActions(state)`。以当前玩家为第一个座位，按顺时针编码其余玩家，最多 4 人，不存在的座位补零。

| 输入 | 内容 |
|---|---|
| 全局 | 当前阶段、终局轮标记、人数、公共筹码、三层牌堆剩余数量 |
| 4 个座位 | 存在标记、筹码、发展卡折扣、分数、预留数量、贵族数量、已购数量、先手标记 |
| 市场 | 全部 12 张公开卡的存在标记、颜色、费用、分值、级别 |
| 自己预留 | 最多 3 张真实身份 |
| 公共贵族 | 最多 5 位的条件 |
| 对手公开预留记忆 | 从公开日志维护已知且尚未购买的预留卡；暗抽不增加已知身份 |

不编码种子、牌堆顺序、未公开预留身份。特征维度 424。数值按可解释范围归一化，不对高折扣或终局高分进行硬裁剪。

每个合法行动 47 维：行动类型、拿取/归还向量、支付向量、目标发展卡、暗抽级别、贵族条件、折后费用和缺色数量。所有黄金支付组合、归还组合、贵族选择均保留。batch 只补齐到当前 batch 最长行动列表，padding logits 屏蔽为极小值。

## 神经网络与优化

- 状态编码器：424 → 128 → 128，Tanh。
- 逐行动评分：拼接状态表示与 47 维行动，175 → 128 → 1，Tanh。
- 价值头：128 → 1。
- 参数 93,698；所有座位共享网络，critic 同样仅看到合法观察。
- 初始 actor 输出层为零；公开的固定 residual prior：购买 `2.5 + 0.35 × 分数 − 0.03 × 支付枚数`，预留 `−0.8`，其他为零。softmax 采样，绝不硬过滤。此先验帮助稀疏终局回报下完成对局，意味着不是完全无先验的从零学习。初始模型评估基线包含同一先验。
- Adam，学习率 3e-4；PPO clip 0.2；value loss 权重 0.5；entropy 权重 0.01；梯度范数上限 0.5。
- 每批完整对局优化最多 4 epochs、minibatch 128；平均 KL 超过 0.03 后停止额外 epochs。未实现学习率调度和 GAE。
- γ = 1，不按步惩罚、不添加分数或卡数奖励。赢局份额 `share`（多人共同胜利时平分），效用 `u=(人数 × share − 1)/(人数−1)`，全体和为零。每个座位所有决策的 Monte Carlo return 为其最终效用。
- 同步采样期间网络固定，旧 log probability 来自实际采样策略；仅对当前模型执行的决策更新，冻结历史模型和贪心策略的动作不混入 PPO 数据。

## 对手池和并行

每局至少一席为当前模型，学习席位与先手独立轮换；其他席位 50% 当前模型、35% 均匀抽样历史模型、15% 贪心基线。每 2 代保存一个历史快照，保留初始模型与最近 5 个快照。所有代模型也单独写盘供人工比较，尚未引入 Elo 联赛或自动“最强模型”晋升。

单个 Python 训练器批量做模型推理，Node worker_threads 各自持有独立规则环境。一次 JSON 消息批量推进多个环境；采样不调用 HTTP 和 UI。CPU 设置单个 PyTorch 计算线程，防止多线程过度竞争。默认 4 个环境，可按机器调整；更多环境不保证线性加速，小网络调度开销可能更大。未实现 CUDA/MPS、跨机分布式和异步参数服务器。

结束状态仍由原规则决定。采样预算超限属于未完成，不伪造赢家或平局；不训练被截断的轨迹。这会带来偏向已完成对局的选择偏差，需监控截断率并在后续考虑价值 bootstrap 或更长预算。

## 评估与 UI

每代针对贪心基线和冻结初始模型，使用与训练不同的固定种子、同一开局交换模型座位。3–4 人时按玩家数循环模型席位，其余席位均为基线，尚未做全座位排列。共享胜利按份额统计；评估结果同时列出完成和截断数量。每代复用的评估种子属于训练监控集，不能当作未见测试集；最终另用 `--evaluate --eval-seed` 做留出评估。

UI 在独立 4175 服务运行：开始/停止/续训、配置并行数、阶段和指标趋势、保存下来的真实对局回放。回放与训练独立，不为了显示而延迟采样；没有模拟浏览器点击训练，也没有虚构实时棋局。完整回放在本机重放原引擎生成公共帧，服务隐藏完整 record，仅提供已完成对局的公开观察。

## 后续实验顺序

先增加训练量并对留出开局做成对统计，确认胜率相对初始模型与基线改善。随后再考虑历史对手优先采样、颜色置换增强、显式卡牌集合编码/注意力、记忆网络和 GPU vector environment。任何扩展均须保持同一规则与观察隔离测试；当前结果不等同于超人水平或均衡策略。
