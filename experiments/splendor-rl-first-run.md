# Splendor 强化学习首轮实验

日期：2026-09-12。实现与使用说明见 [AI 实验室](../agents/splendor-rl/README.md)，设计见 [DESIGN](../agents/splendor-rl/DESIGN.md)。[机器可读指标](splendor-rl-first-run.json)保存逐代结果与配置。

## 运行结果

本地 Apple Silicon、Python 3.12.12、PyTorch 2.14.0、NumPy 2.5.3；CPU 单个 PyTorch 线程、4 个 Node 规则环境。网络参数 93,698。先以 8 局/代做 2 代冒烟训练，再从 checkpoint 恢复，以 32 局/代训练 40 代，到第 42 代。

| 项目 | 实测 |
|---|---:|
| 40 代采样对局 | 1,280 |
| 正常结束 | 1,273 |
| 达到 800 次决策预算 | 7（0.55%） |
| 采样速度中位数 | 2,733 决策/秒 |
| 参数更新 | 每代均非零，loss / gradient 有限 |
| 3 人、4 人额外冒烟训练 | 各 4 局，全部完成并更新模型 |

采样速度仅覆盖 rollout 收集阶段，不包括模型优化、评估、启动 worker 或保存回放，不能当作全流程吞吐或跨机器保证。未运行单环境/多环境严格对比，不能宣称 4 倍加速。

## 未见开局评估

训练监控使用种子 908172；留出测试改用 177013，同一 50 个开局各交换一次模型座位，共 100 局，对手均为公开的贪心基线。初始模型使用保存的初始策略权重（包含同一购牌先验），不是随机合法行动基线。

| 模型 | 完成 | 胜局份额 |
|---|---:|---:|
| 初始模型 | 100 / 100 | 13% |
| 第 42 代 | 100 / 100 | 22% |

差值 +9 个百分点。以每个开局的两个交换座位结果为一个单元，对 50 个单元做 10,000 次 paired bootstrap（种子 7），95% 区间约为 **−1 至 +19 个百分点**，包含 0。因此只能说观察到正向点估计，不能宣称已证明稳定提升。模型当前仍明显弱于贪心基线，尚不具备强棋力或均衡策略证据。

## 验证完成

- 游戏原 30 项测试和 30 局规则模拟通过。
- 3 项 JS 特征测试：2–4 人维度、动态行动、隐藏信息不影响编码、公开预留记忆。
- 5 项 Python 测试：公共服务读写限制、实际梯度和 checkpoint、截断不判平、并行可重复采样及合法回放、共同获胜效用。
- UI 实测开始新训练、停止后保留 checkpoint、从第 42 代继续到第 44 代；自我对弈/评估列表正常，逐步及播放可用，原图加载，无控制台错误。
- 原 4173 手动对局未重置；实验室独立运行于 4175。

训练时源码处于工作区，配置记录当时 HEAD；本报告提交的后续改动增加回放种类、源码哈希记录与 UI 文案，没有更改报告使用的策略网络、奖励或 PPO 参数。首轮采样把保证为当前模型的席位设为先手；后续已将学习席位与先手解耦轮换，以降低先手偏差。表中结果仍是修订前第 42 代的真实评估，不冒充新采样方式的结果。新的运行会逐文件记录源码 SHA-256。

## 边界

这是已运行的强化学习基础设施与初步模型，不是完成长期训练的强 AI。每代固定监控集不是独立测试集；7 个截断对局已排除出梯度，存在完成样本选择偏差。暂未实现跨机器训练、GPU 采样、自动 Elo 晋升、全座位排列评估或在线人机匹配。UI 播放已完成对局，不卡住训练来逐帧直播。
